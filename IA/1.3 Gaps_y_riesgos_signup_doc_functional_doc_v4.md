### 2.2. Veredicto de QA
> **Dictamen:** **APROBADO PARA AUTOMATIZACIÓN WEB UI (Selenium + Cucumber BDD)**
>
> **Síntesis:** Se resolvieron las discrepancias críticas identificadas en el documento v4.0. Se acordó que la automatización de `PetStoreAutomation` se ejecutará **100% sobre la capa Web UI** interactuando con el formulario HTML real, descartando la dependencia de contratos JSON `REG_*` no implementados. Asimismo, se fijó que las validaciones operan del lado del servidor (tras enviar el formulario), se definió la regla exacta para el formato telefónico (`^\+?[0-9]{9}$`), se adoptó el set estándar completo de caracteres especiales para contraseñas y se autorizó la generación sintética de usuarios en el ambiente de pruebas.

## 6. Registro de Acuerdos de Negocio (Product Owner / QA Lead)

Formalización de las decisiones tomadas el **29 de octubre de 2026**:

1. **Acuerdo 1 (Arquitectura de Pruebas):** Enfoque 100% Web UI con Selenium WebDriver para el flujo de Sign Up en `PetStoreAutomation`.
2. **Acuerdo 2 (Capa de Validación):** Validación de reglas de negocio ejecutada en backend/servidor al enviar el formulario; no se exigirá validación en tiempo real de frontend.
3. **Acuerdo 3 (Regla de Teléfono):** Formato `^\+?[0-9]{9}$` (exactamente 9 dígitos numéricos con `+` opcional).
4. **Acuerdo 4 (Caracteres de Contraseña):** Conjunto estándar completo de caracteres especiales soportado.
5. **Acuerdo 5 (Ambiente de Pruebas):** Autorizada la ejecución de pruebas y creación de cuentas sintéticas en `https://petstore.octoperf.com/account/new`.

## 7. Criterios de Aceptación Refinados (Gherkin para Cucumber)

Estos escenarios sustituyen los esquemas de API JSON de la especificación original y quedan listos para implementarse en `src/test/resources/Feature/Create_user/CreateUser.feature`:

### Escenario 1: Registro exitoso de nueva cuenta (Flujo Feliz)
```gherkin
@web @smoke @signup
Escenario: Registro exitoso con datos válidos completos
  Dado que el usuario navega a la página de registro de PetStore
  Cuando ingresa un User ID único de 10 caracteres alfanuméricos
  Y completa una contraseña válida de 10 caracteres con mayúsculas, minúsculas, números y caracteres especiales
  Y confirma la contraseña exactamente igual
  Y completa sus datos personales con First Name "Carlos" y Last Name "Tester"
  Y completa un email único con formato válido
  Y completa un teléfono válido de 9 dígitos con prefijo internacional
  Y completa la dirección obligatoria "Calle 123", ciudad "Bogotá", estado "Cundinamarca", zip "110111" y país "Colombia"
  Y selecciona sus preferencias de perfil
  Y hace clic en el botón "Save Account Information"
  Entonces el sistema redirige al usuario a la página de inicio "/catalog"
  Y la cabecera muestra el enlace "Sign In", confirmando que la sesión no fue iniciada automáticamente
```

### Escenario 2: Intento de registro con User ID duplicado
```gherkin
@web @negative @signup
Escenario: Rechazo de registro por User ID duplicado (insensible a mayúsculas)
  Dado que existe un usuario registrado previamente con User ID "TESTUSER01"
  Cuando un nuevo usuario intenta registrarse usando el User ID "testuser01"
  Y completa el resto de campos obligatorios con valores válidos
  Y hace clic en el botón "Save Account Information"
  Entonces el sistema no completa el registro y permanece en la página de cuenta
  Y el formulario conserva los datos previamente ingresados excepto los campos de contraseña
```

### Escenario 3: Contraseña no coincide con la confirmación
```gherkin
@web @negative @signup
Escenario: Rechazo de registro por discrepancia en confirmación de contraseña
  Dado que el usuario se encuentra en el formulario de registro
  Cuando ingresa una contraseña válida "Passw0rd!+"
  Y en el campo Repeat Password ingresa "Passw0rdDifferent!+"
  Y completa los demás campos obligatorios
  Y hace clic en el botón "Save Account Information"
  Entonces el sistema no procesa el alta de la cuenta
  Y solicita la confirmación exacta de la contraseña
```

### Escenario 4: Envío con campos obligatorios vacíos
```gherkin
@web @negative @signup
Esquema del escenario: Validación de campos obligatorios faltantes
  Dado que el usuario se encuentra en el formulario de registro
  Cuando deja el campo obligatorio "<campo_omitido>" vacío
  Y completa los demás datos requeridos
  Y hace clic en el botón "Save Account Information"
  Entonces el sistema impide la creación de la cuenta
  Y muestra un mensaje de validación indicando la obligatoriedad del campo

  Ejemplos:
    | campo_omitido |
    | username      |
    | password      |
    | firstName     |
    | lastName      |
    | email         |
    | address1      |
```
